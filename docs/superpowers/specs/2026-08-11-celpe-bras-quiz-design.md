# Тренажёр для подготовки к Celpe-Bras — дизайн

Дата: 2026-08-11

## Задача

Набор простых веб-викторин для самостоятельной подготовки к экзамену Celpe-Bras
(сертификат владения бразильским португальским). Плюс репозиторий для накопления
учебных материалов: примеров экзаменационных заданий, конспектов, шпаргалок.

Пользователь — один человек, готовящийся к экзамену. Приложение публикуется на
GitHub Pages, чтобы заниматься с любого устройства, включая телефон.

## Разделы

1. **Виды текстов.** Экзамен требует написать текст в заданном жанре: письмо в
   редакцию, записка соседу, манифест, заявление. У каждого жанра свой регистр,
   своё вступление и заключение. Вопрос задаёт ситуацию («напиши записку
   друзьям»), варианты — наборы формул разных регистров; нужно выбрать уместный.
2. **Артикли.** Мужской и женский род, сложные случаи, исключения, употребление
   со странами и городами.
3. **Предлоги.** em, na, no, por, para, pelo и слитные формы.
4. **Акценты.** Где ставятся `á â ã à ç ê ó ô õ`, по каким правилам.
5. **Вводные конструкции** (`conectivos`) для письменной части: em primeiro
   lugar, além disso, portanto, em suma.

## Стек

Статический сайт без сборки: HTML + ES-модули + CSS. Без npm, без CI, без
зависимостей.

Обоснование: логики в проекте мало, контента много. Основная работа —
редактирование вопросов, и правка одного слова не должна требовать пересборки.
Отсутствие зависимостей означает, что проект не сломается от того, что им
полгода не занимались. Деплой на GitHub Pages сводится к `git push`.

Цена решения: нет типов и нет компонентов, разметка пишется руками. Для проекта
такого размера это приемлемо.

## Структура

```
CelpeBras/
├── index.html            — главная: список разделов и прогресс по каждому
├── quiz.html             — универсальная страница викторины (?s=<id раздела>)
├── assets/
│   ├── style.css
│   ├── data.js           — загрузка JSON и сообщения об ошибках загрузки
│   ├── engine.js         — чистая логика: перемешивание, сессия прохождения
│   ├── storage.js        — localStorage: результаты и накопленные ошибки
│   ├── quiz-page.js      — рендер страницы викторины
│   └── index-page.js     — рендер главной
├── tests/
│   └── engine.test.mjs   — тесты чистой логики (node --test)
├── data/
│   ├── sections.json     — реестр разделов
│   ├── tipos-de-texto.json
│   ├── artigos.json
│   ├── preposicoes.json
│   ├── acentos.json
│   └── conectivos.json
├── materiais/            — примеры заданий, конспекты, шпаргалки
├── tools/
│   └── validate.mjs      — проверка целостности данных, чистый Node без пакетов
└── docs/superpowers/specs/  — спеки
```

`tools/validate.mjs` — единственный код вне сайта. Он не участвует в работе
приложения и не требует установки пакетов, поэтому решение «без сборки и
зависимостей» сохраняется.

Одна страница викторины обслуживает все разделы. Добавление нового раздела =
новый JSON плюс строка в `sections.json`. HTML не копируется.

## Модель данных

`data/sections.json` — реестр:

```json
[
  {
    "id": "tipos-de-texto",
    "title": "Виды текстов",
    "description": "Какие формулы к какому жанру относятся",
    "file": "tipos-de-texto.json"
  }
]
```

Файл раздела — массив вопросов единого формата:

```json
{
  "id": "art-001",
  "prompt": "___ Brasil é um país enorme.",
  "options": ["O", "A", "—", "Os"],
  "answer": 0,
  "explanation": "Страны обычно с артиклем: o Brasil, o Japão, a França. Без артикля — Portugal, Angola, Israel, Cabo Verde.",
  "tags": ["países"]
}
```

Поля:

- `id` — уникален внутри раздела, служит ключом прогресса в localStorage.
  Менять `id` существующего вопроса нельзя: это обнулит его статистику.
- `prompt` — текст вопроса. Пропуск обозначается `___`.
- `options` — 3–5 вариантов. Переносы строк (`\n`) внутри варианта допустимы и
  рендерятся как есть (`white-space: pre-line`) — так устроен раздел 1, где
  вариант представляет собой блок из нескольких формул.
- `answer` — индекс правильного варианта в исходном (неперемешанном) массиве.
- `explanation` — обязательное поле. Викторина без объяснения проверяет, но не
  учит.
- `tags` — необязательные метки темы внутри раздела (`países`, `crase`).

Все разделы используют один формат. Различие между разделами — только
содержимое JSON, поэтому движок пишется один раз.

## Тип вопроса

Поддерживается ровно один тип: выбор одного варианта из нескольких. Он
покрывает все пять разделов. Ввода текста и перетаскивания нет.

Если для акцентов понадобится задание вида «расставь диакритику в слове», это
будет отдельный тип, добавленный позже отдельной итерацией.

## Поведение

**Главная (`index.html`).** Список разделов из `sections.json`. У каждого —
название, описание, число вопросов и процент освоения из localStorage. Ссылка
ведёт на `quiz.html?s=<id>`.

**Викторина (`quiz.html`).** При загрузке читает `?s=`, подгружает JSON раздела,
перемешивает вопросы и варианты внутри каждого вопроса. Показывает по одному
вопросу.

После выбора варианта:

- выбранный вариант подсвечивается верным или неверным;
- правильный вариант подсвечивается всегда, даже при ошибке;
- показывается `explanation`;
- дальнейшие клики по вариантам игнорируются;
- появляется кнопка перехода к следующему вопросу.

По окончании — экран результата: счёт, список вопросов с ошибками и кнопка
«повторить только ошибки», которая перезапускает викторину на этом подмножестве.

**Прогресс.** В localStorage под ключом вида `celpe:<sectionId>` хранится, по
каждому `id` вопроса, число верных и неверных ответов, а также флаг последнего
ответа. Процент освоения раздела = доля вопросов, на которые последний ответ
был верным. Ошибочные вопросы накапливаются между сессиями, так что «повторить
ошибки» доступно и при новом заходе.

Данные хранятся только в браузере. Синхронизации между устройствами нет —
на телефоне будет свой прогресс. Это осознанное упрощение: бэкенда в проекте
нет.

**Сброс прогресса.** Повторное прохождение раздела сброса не требует: вопросы
перемешиваются заново, счёт попытки всегда считается с нуля. Сбрасывается
именно накопленная статистика — та, что даёт процент освоения и подпитывает
режим «повторить ошибки».

- У каждого раздела на главной — кнопка сброса статистики этого раздела
  (удаляет ключ `celpe:<sectionId>`).
- Внизу главной — кнопка сброса всего прогресса (удаляет все ключи с префиксом
  `celpe:`, не трогая остальной localStorage домена).

Обе кнопки запрашивают подтверждение и называют, что именно будет стёрто.
Данные нигде не дублируются, отменить сброс нечем.

## Оформление и вёрстка

Минимализм: на экране только то, что нужно для текущего вопроса. Никаких
логотипов, боковых панелей, декоративных блоков. Внимание должно уходить в
текст на португальском, а не в интерфейс.

**Mobile-first.** Базовые стили пишутся под узкий экран, широкий получает их
же с ограничением ширины. Одна колонка, контент по центру, `max-width: 40rem`.
Медиазапросы — только там, где узкий макет реально ломается; ожидается один-два
на весь проект. Горизонтального скролла нет ни при какой ширине.

**Никаких внешних ресурсов.** Ни CSS-фреймворков, ни иконочных библиотек, ни
подключаемых шрифтов: это противоречило бы решению обходиться без зависимостей
и добавило бы сетевые запросы к чужим доменам. Шрифт — системный стек
(`system-ui`), он корректно отображает португальскую диакритику на всех
платформах и не даёт скачка шрифта при загрузке.

**Палитра** задаётся CSS-переменными в `:root`. Нейтральный фон, тёмный текст,
один акцентный цвет для интерактивных элементов. Тёмная тема — через
`prefers-color-scheme: dark`, переопределением тех же переменных.

**Состояния ответа различимы не только цветом.** Верный вариант помечается
галочкой, неверный — крестиком, плюс изменением рамки. Цвет — дополнительный
сигнал, а не единственный: иначе интерфейс ломается при дальтонизме и в
контрастных режимах.

**Тач-цели.** Вариант ответа — карточка во всю ширину колонки, высотой не менее
`2.75rem`, с зазором между вариантами, чтобы не промахиваться пальцем. Кнопка
«следующий вопрос» — внизу экрана, в зоне большого пальца.

**Типографика** масштабируется через `clamp()`, чтобы не заводить брейкпоинты
ради размера шрифта. Длинные варианты раздела 1 (блоки формул в несколько
строк) рендерятся с `white-space: pre-line` и уменьшенным кеглем.

**Клавиатура на ноутбуке.** Цифры `1`–`4` выбирают вариант, `Enter` или пробел
переходят к следующему вопросу. Видимый фокус (`:focus-visible`) не убирается.

**Анимации** — только короткие переходы состояния (появление объяснения,
подсветка ответа), и те отключаются при `prefers-reduced-motion: reduce`.

## Обработка ошибок

- Нет параметра `?s=` или указан неизвестный раздел — сообщение и ссылка
  на главную.
- JSON раздела не загрузился или сломан — сообщение об ошибке с именем файла,
  без белого экрана.
- Пустой массив вопросов — сообщение «в разделе пока нет вопросов».
- localStorage недоступен (приватный режим) — викторина работает, прогресс не
  сохраняется, приложение не падает.
- Открытие через `file://` — `fetch` к JSON заблокирован браузером. На странице
  выводится подсказка запустить `npx serve`.

## Проверка

Тестами покрывается только `engine.js` — чистая логика без DOM и без
хранилища. Причина: `prepareQuestions` перемешивает варианты ответа и
переносит признак правильности с индекса на сам вариант. Ошибка в этом месте
даёт викторину, которая молча засчитывает неверный ответ, — и заметить это
при ручном прогоне почти невозможно. Тесты пишутся на встроенном `node --test`,
так что решение «без зависимостей» не нарушается.

Остальное — рендер, загрузка данных, `localStorage` — проверяется вручную:
объём логики там мал, а её отказы видны сразу.

Кроме тестов:

- скрипт-валидатор `tools/validate.mjs` (запускается `node tools/validate.mjs`)
  проверяет каждый файл раздела: уникальность `id`, наличие `explanation`,
  `answer` в границах массива `options`, отсутствие дублей среди вариантов,
  соответствие `sections.json` наличию файлов;
- ручной прогон каждого раздела после наполнения: пройти до конца, проверить
  ошибочный ответ, перезагрузить страницу и убедиться, что прогресс сохранился.

## Материалы

`materiais/` — папка репозитория, не часть приложения. Примеры экзаменационных
заданий, конспекты, шпаргалки. Когда из материала можно сделать вопросы, он
перегоняется в JSON соответствующего раздела.

## Деплой

`git init` локально. Публикация на GitHub и включение Pages — по отдельной
команде пользователя. Сборки нет: деплой = `git push`, Pages отдаёт корень
ветки `main`.

Локальный просмотр — `npx serve` в корне проекта.

## Объём первой итерации

Каркас (главная, страница викторины, движок, хранилище, валидатор) и по 6–8
вопросов в каждом из пяти разделов. Пользователь смотрит формат и правит
формулировки, после чего разделы наполняются объёмом.

## Что сознательно не делается

- Аккаунты, бэкенд, синхронизация между устройствами.
- Интервальное повторение (SRS) — накопления ошибок достаточно на старте.
- Аудирование и работа с текстами экзамена — отдельные разделы, вне этой итерации.
- Типы вопросов помимо выбора одного варианта.
